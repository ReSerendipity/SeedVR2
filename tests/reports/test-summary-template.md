## 4. 测试策略

[描述测试方法和策略，如：]

本次测试采用以下策略：

1. **自动化测试**：使用 Playwright 编写 E2E 测试用例，覆盖功能、安全、性能和可访问性
2. **API Mock**：通过 Playwright Route API 模拟后端响应，确保测试独立于后端服务
3. **安全测试**：注入恶意载荷（XSS、路径遍历等），验证前端防护机制
4. **性能测试**：使用 PerformanceObserver API 采集 Core Web Vitals 指标
5. **可访问性测试**：使用 axe-core 引擎检测 WCAG AA 违规项
6. **探索性测试**：人工检查交互细节、边界场景和视觉一致性

## 9. 风险评估

### 9.1 高风险区域

[列出测试中发现的高风险区域，如：]

1. **目录浏览器 innerHTML 注入** — 使用 `innerHTML` 渲染文件名，存在 XSS 攻击面
2. **CORS 配置缺失** — 跨域场景下 API 请求被拦截，影响前后端分离部署
3. **SSE 连接稳定性** — 长时间运行任务时 SSE 连接可能断开，缺少自动重连机制

### 9.2 已知问题

[列出已知但未修复的问题，如：]

1. 大文件上传时进度条偶尔不更新（非阻塞，可通过刷新恢复）
2. 暗色主题下部分图标对比度不足（Minor，不影响功能）
3. 设置页面保存后偶发 Toast 不显示（Minor，数据实际已保存）

### 9.3 未测试区域

[列出本次未覆盖的测试区域，如：]

1. 多文件批量上传场景
2. 网络断开后的离线行为

## 13. 建议

### 13.1 发布决策 (Go/No-Go)

| 决策 | [如：⚠️ 有条件通过 (Conditional Go)] |
|------|------|

**理由**：[如：核心功能基本可用，但存在 1 个 Critical 级别安全缺陷（innerHTML XSS）和 1 个 Major 级别缺陷（CORS 配置），需在发布前修复。]

### 13.2 发布前必须修复的缺陷

1. **BUG-0002** — innerHTML XSS 注入风险（Critical / P0）— 必须替换为 textContent 或转义处理
2. **BUG-0001** — CORS 配置缺失（Major / P1）— 必须添加 CORSMiddleware 配置

### 13.3 发布后监控建议

1. 监控 SSE 连接断开率，关注长时间运行任务的进度推送稳定性
2. 监控大文件上传的成功率和耗时
3. 关注用户反馈中暗色主题对比度问题
4. 上线后进行一轮生产环境安全扫描（OWASP ZAP / Burp Suite）
5. 监控浏览器控制台错误日志，关注未捕获的 Promise rejection
